# Changelog

## [Unreleased]

### Fixed

- Seed tidak lagi mengaktifkan ulang identitas kanal yang sudah dicabut: `apply_seed` berjalan tiap gateway dimulai dan dulu menulis `status` dari seed (bawaan `aktif`), sehingga ikatan yang dicabut `identity.revoked` aktif lagi setelah restart dan kembali menerima notifikasi serta perintah chat. Status `dicabut` di basis data kini dipertahankan (temuan audit 2026-11-13).
- wa-bridge: Baileys 6.7.24 (tag npm `legacy`) diganti 7.0.0-rc14. WhatsApp kini memakai sesi Signal beralamat LID, sehingga dengan 6.7.24 setiap pesan keluar gagal didekripsi HP pada percobaan pertama dan baru sampai setelah 2-4 permintaan kirim ulang. Sesi tertaut lama dimigrasi otomatis (tanpa pindai QR ulang). Pesan masuk beralamat LID memakai nomor dari `remoteJidAlt`. libsignal diambil dari registry npm (bukan git).
- wa-bridge: kunci Signal dibungkus `makeCacheableSignalKeyStore` agar baca-tulis berkas sesi berkurang (sebelumnya 134 galat `Bad MAC` dan 12 putus `badSession` 500 dalam 20 jam). Log `status_kirim` (hanya id pesan) untuk memantau pengiriman.
- wa-bridge: libsignal tidak lagi mencetak isi sesi Signal (termasuk kunci privat ratchet) ke log kontainer; output `console` dibungkam dan `console.error` dicatat sebagai teks pendek lewat pino.
- `/antrean` tidak lagi menerima argumen band: Command Facade api (`queue`) menolak argumen apa pun, sehingga `/antrean <band>` selalu gagal "argumen perintah tidak sesuai". Teks bantuan disesuaikan.

### Added

- Log pengiriman untuk halaman web `/deliveries`: `GET /internal/v1/outbox?status=` (200 pesan terbaru, tanpa isi pesan dan penerima) dan `POST /internal/v1/outbox/{id}/retry` (hanya pesan `dead`, kembali `pending` dengan jatah percobaan baru, audit `outbox.retry`), untuk `api` dan `config`. Stempel waktu di respons internal kini selalu ber-zona UTC; SQLite membuang zona sehingga jam di web bergeser 7 jam.
- Pairing chat (GW§3.3): pengirim yang belum terhubung boleh mengirim `/daftar <kode>` (kode dari halaman Identitas web). Gateway mengklaim kode lewat api `POST /svc/v1/pairing/claim` (HMAC `gateway`, `external_id_hash` HMAC berkunci, bukan nomor mentah), lalu mengikat chat ke pemilik kode; ikatan lama yang dicabut untuk chat yang sama diaktifkan ulang. Kode salah, terpakai, atau kedaluwarsa dibalas langsung tanpa ikatan; 429 dan Core mati dibalas sesuai. Balasan "tidak terdaftar" kini menyebut `/daftar`. `/daftar` dari chat yang sudah terhubung dibalas "sudah terhubung".
- Tautan bot WhatsApp dari web: `GET /internal/v1/whatsapp/link` (status, nomor tersamar, QR data URL PNG saat perlu pindai) dan `POST /internal/v1/whatsapp/link/logout` (putuskan tautan; audit `whatsapp.unlinked`), untuk `api` dan `config`. Nilai dari wa-bridge disaring (QR hanya `data:image/png;base64`, nomor hanya bentuk tersamar). wa-bridge menambah `GET /tautan` dan `POST /keluar` ber-Bearer token; `/qr` terbuka tetap hanya di 127.0.0.1.
- `/berhenti`: pengguna memutus sendiri ikatan chat-nya (status `dicabut`, audit `identity.unpaired`, balasan langsung karena outbox tidak mengirim ke identitas dicabut); `/daftar <kode>` menghubungkan lagi. Teks bantuan memuat `/berhenti`.
- Endpoint internal menerima token layanan EdDSA dari identity (audiens `svc:gateway`) untuk pemanggil yang diizinkan, selain HMAC. api memanggil gateway dengan token itu, sehingga sebelumnya `/identities` web dan status gateway di api selalu 401 di gateway (502 "Layanan sedang tidak tersedia" di web).
- `GET /internal/v1/identities` dan `DELETE /internal/v1/identities/{id}` (`api` atau `config`) untuk halaman Identitas web: daftar ikatan tanpa ID chat atau nomor, dan cabut ikatan (idempoten, audit `identity.binding_revoked`, 404 untuk id tidak dikenal).
- `ASTRIA_GW_TELEGRAM_ENABLED` (bawaan `true`): `false` mematikan adapter dan poller Telegram walau kunci induk vault ada, untuk lingkungan yang hanya memakai surel dan WhatsApp (keputusan PM 2026-11-12). Tanpa ini Telegram terpasang menunggu token dari config dan `/health` gateway selalu `degraded`.
- Rahasia kanal dari config dan pencabutan identitas: `PUT /internal/v1/secrets/{key}` dari config (HMAC `config` saja, 204 tanpa nilai, idempoten; kunci `telegram.bot_token` dan `smtp.password`, 404 untuk kunci lain, 422 untuk format token salah, 409 bila dikunci env, 503 bila kunci induk belum diisi). Rahasia disimpan di tabel `secret` dengan AES-256-GCM (AAD = nama kunci), dibaca ke memori saat start, dan dipakai per panggilan oleh adapter Telegram dan SMTP. Konfigurasi baru: `ASTRIA_GW_MASTER_KEY` atau `_FILE` (32 byte, base64 atau hex). Event kontrol `identity.revoked` (`channel_id` "*") mencabut semua ikatan kanal aktif milik `user_id` (status `dicabut`), idempoten lewat `event_inbox`; pesan dari chat itu tidak lagi diterjemahkan jadi perintah, dan pesan yang masih antre gagal permanen (`identitas_tidak_aktif`). Telegram aktif juga bila kunci induk diisi, supaya token bisa ditulis config.
- Kanal WhatsApp uji (keputusan PM 2026-11-10): jembatan `wa-bridge/` (Node, Baileys 6.7.24, `GET /qr`, `GET /status`, `POST /kirim` ber-Bearer token, penerusan pesan teks pribadi ke gateway, Dockerfile non-root, uji `node --test`); tipe kanal `whatsapp` di seed (`external_id` 8-15 digit); adapter outbox `whatsapp`; `POST /internal/v1/whatsapp/masuk` di listener internal dengan Bearer token dan dedupe; pemrosesan perintah chat dipindah ke `inbound.py` dan dipakai bersama poller Telegram; `GET /internal/v1/status` melaporkan `whatsapp`. Konfigurasi baru: `ASTRIA_GW_WA_BRIDGE_URL`, `ASTRIA_GW_WA_BRIDGE_TOKEN_FILE`, `ASTRIA_GW_WHATSAPP_CHANNEL_ID`.
- gateway#3 (notifikasi keluar dulu): dua listener dalam satu proses (internal `/internal/v1`, publik hanya `/hooks/*` yang kini selalu 404, batas body 64 KiB); `POST /internal/v1/events` dari notifier dengan HMAC `astria_common.hmac_auth`, dedupe `event_id` (409), allowlist payload (422), kanal tidak dikenal (404); `GET /internal/v1/status`; tabel `channel_config`, `channel_identity`, `outbox_message`, `inbound_message`, `event_inbox`, `poll_state`, `pending_confirmation`, `gw_audit` (SQLAlchemy Core, PostgreSQL dan SQLite); seed kanal dan identitas dari berkas JSON; pekerja outbox dengan adapter Telegram (httpx) dan SMTP (aiosmtplib); poller Telegram `getUpdates` dengan tata bahasa tertutup, batas laju, dan perintah T0 ke Command Facade api. Dependensi baru: `httpx`, `aiosmtplib`.
- Kerangka layanan Tahap 0 dari templat `common` v0.1.0: `/health`, `/ready`, `/metrics`, token layanan, Dockerfile non-root, CI (lint, uji, gitleaks, build image, smoke `/ready`).
- Logo Astria di kepala README (`.github/assets/`, dari kit logo di repo `triase-dfir-uiux`).
